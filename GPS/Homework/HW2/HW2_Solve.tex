\section*{Problem 3}
\subsection*{(a.)}
\hspace*{2em}The function is shown below, it is capable of using multiple rows of ECEF and calculating
azimuth, elevation, and range. It is repeated again later in the MATLAB code section. 
\begin{verbatim}
function [AZ, EL, RANGE] = compute_azelrange(userECEF, satECEF)
% satECEF is ECEF vector of sat
% userECEF is ECEF vector of the user

% Calculate LLA from userECEF
lla = ecef2lla(userECEF,'WGS84');
ref_lat = lla(1);
ref_lon = lla(2);
altitude = lla(3);
% Take difference of ECEF vectors, conver to ENU depending on ref angle
r_ECEF = satECEF-userECEF;

% Calculting range.
RANGE = sqrt(sum(r_ECEF.^2,2));

% Converting to ENU frame
r_ENU = (ECEF2ENU(ref_lat,ref_lon)*r_ECEF')';
x_E = r_ENU(:,1);
x_N = r_ENU(:,2);
x_U = r_ENU(:,3);

% Calclating azimuth and elevation
AZ = atan2d(x_E,x_N);
EL = asind(x_U./sqrt(sum(r_ENU.^2,2)));

end
\end{verbatim}
\hspace*{2em}We can actually check this function by emulating a satellite directly overhead
NIST and feeding it into the function.

\begin{verbatim}
[az_test, el_test, range_test] = compute_azelrange(ecef_NIST, 5*ecef_NIST)

az_test =

  180.0000


el_test =

   89.8107


range_test =

   2.5484e+07

\end{verbatim}

\hspace*{2em}From above we can see that the function works because with a satellite directly overhead,
the function returns an elevation angle of $90\deg$, and an azimuth of $180\deg$. These angles geometrically
make sense and the resulting range is 5 times the magnitude of NIST's ECEF vector which is also reasonable.

\subsection*{(c.)}
\hspace*{2em}We are able to observe the differences in each Skyplot. NIST and SMEAD look strikingly
similar with very small shifts in movements and which satellites are visible due to their close proximity
to each other on Earth. This naturally results in skyplots that look similar, there would not be much change between
the visibility when they are this close. In those skyplots we can observe a large gap in visibility above ~$60\deg$ in elevation
between ~$320\deg$ and ~$40\deg$ in azimuth, likely a result from the satellite orbits and that specific location
on Earth. There is greater difference when comparing the skyplot at the Equator. Here there is far more coverage, likely due to it being
at the Equator and able to see more of the GPS constellation over time. 
\hspace*{2em}This is not fully representative of what these sights will actually see because of this model
neglecting environmental factors. For example, for the NIST and SMEAD sights, the literally big thing that this model
does not account for in its elevation mask are the mountains. Mountains would obstruct some line of sight with
the GPS satellites that would have been in view otherwise.

function C_ECEF2ENU = ECEF2ENU(ref_lat_deg, ref_lon_deg)

phi = ref_lat_deg;
lambda = ref_lon_deg;

R1 = [1 0 0;
    0 cosd(90-phi) sind(90-phi);
    0 -sind(90-phi) cosd(90-phi)];

R2 = [-sind(lambda) cosd(lambda) 0;
    -cosd(lambda) -sind(lambda) 0;
    0 0 1];

C_ECEF2ENU = R1*R2;

end

function [AZ, EL, RANGE] = compute_azelrange(userECEF, satECEF)
% satECEF is ECEF vector of sat
% userECEF is ECEF vector of the user

% Calculate LLA from userECEF
lla = ecef2lla(userECEF,'WGS84');
ref_lat = lla(1);
ref_lon = lla(2);
altitude = lla(3);
% Take difference of ECEF vectors, conver to ENU depending on ref angle
r_ECEF = satECEF-userECEF;

% Calculting range.
RANGE = sqrt(sum(r_ECEF.^2,2));

% Converting to ENU frame
r_ENU = (ECEF2ENU(ref_lat,ref_lon)*r_ECEF')';
x_E = r_ENU(:,1);
x_N = r_ENU(:,2);
x_U = r_ENU(:,3);

% Calclating azimuth and elevation
AZ = atan2d(x_E,x_N);
EL = asind(x_U./sqrt(sum(r_ENU.^2,2)));

end
