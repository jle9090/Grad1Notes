\section*{Problem 4: Observed Minus Computed (Expected) Range}

    \caption{PRN5 C1C Pseudorange vs Expected Range}
    \label{fig:PRN5 C1C Pseudorange vs Expected Range}
\end{figure}

\begin{figure}[H]
    \centering
    \includegraphics[width=0.6\textwidth]{../MATLAB/figures/HW3_P4_residuals_PRN5.png}
    \caption{PRN5 C1C Pseudorange vs Expected Range Residuals}
    \label{fig:PRN5 C1C Pseudorange vs Expected Range Residuals}
\end{figure}

\hspace*{2em}We are able to observe the differences between the reported pseudoranges and
the expected range calculated previously in Figure \ref{fig:PRN5 C1C Pseudorange vs Expected Range}
and  Figure \ref{fig:PRN5 C1C Pseudorange vs Expected Range Residuals}. They generally match up, however there 
are residuals of up to $85\,\mathrm{km}$. The biggest differences between them are likely a result of the correction being 
done to find the expected range. The ephemeris broadcast, conversion to position, and subsequent correction we performed would
be much more accurate than the pseudorange that is being reported. The pseudorange afterall is affected by propogation effects in the
atmosphere (tropospheric effects, ionospheric effects) which cause these errors observed between the two ranging measurements 
being reported.

\hspace*{2em}Proof can be shown when examining these results for PRN 11 which is done for problem 5
as well. Examining Figures \ref{fig:PRN11 C1C Pseudorange vs Expected Range} and \ref{fig:PRN11 C1C Pseudorange vs Expected Range Residuals},
we see residuals in the same magnitude as seen in Figures \ref{fig:PRN5 C1C Pseudorange vs Expected Range} and \ref{fig:PRN5 C1C Pseudorange vs Expected Range Residuals}.
This means that throughout this process, the difference is not a result from using a different GPS satellite, PRN 11 and PRN 5
are in different satellite blocks and would be in view of NIST at different times through their orbits. The factors that would affect 
pseudoranging in this case that would not be due to the GPS satellites would be atmospheric effects and the clock errors in the GPS
receiver at the ground station. Additional evidence at this being a clock error issue is examining the clock
errors plotted from Problem 2, Figure \ref{fig:Clock Bias}. Here we can see an clock bias error of about $70\,\mathrm{km}$.
The same magnitude of error that we observe in the psuedorange and expected range residuals.

function R_expected = compute_expected_range(ephemeris, week, tow, PRN_number, receiver_ECEF)
% Computes expected range by iteration

% Constants for the alg
c  = 2.99792458e8; % speed of light, m/s
wE = 7.2921151467e-5; % Earth rotation rate, rad/s

% Step 1: Satellite ECEF position at Tr initially.
Tr = tow + week*604800;
[~, satPos, ~, ~] = eph2pvt2025(ephemeris, [week tow], PRN_number);

% Step 2: Geometric range using NIST_ECEF and satPos at Tr
% Reuse azel range for convinience
[~, ~, R] = compute_azelrange(receiver_ECEF, satPos);

% Iterate until range converges
% Step 3: initial time of transmission
Tt = Tr - (R/c);
R_expected = R;

for iter = 1:5
    % Step 3: time of transmission in gps week number and TOW
    Tt_week = floor(Tt/604800);
    Tt_tow  = Tt - Tt_week*604800;

    % Step 4: satellite ECEF position at Tt
    [~, satPos_Tt, ~, ~] = eph2pvt2025(ephemeris, [Tt_week Tt_tow], PRN_number);

    % Step 5: rotate sat position into the ECEF frame
    % Sat position from receiver
    x = satPos_Tt(:,1);
    y = satPos_Tt(:,2);
    z = satPos_Tt(:,3);

    phi = wE .* (Tr - Tt);
    x_ECEF =  x.*cos(phi) + y.*sin(phi);
    y_ECEF = -x.*sin(phi) + y.*cos(phi);

    satPos_Tt_ECEF = [x_ECEF, y_ECEF, z];

    % Step 6: recompute geometric range with the rotated sat position
    [~, ~, R_new] = compute_azelrange(receiver_ECEF, satPos_Tt_ECEF);

    % Convergeance condition
    if max(abs(R_new - R_expected)) < 1e-4
        R_expected = R_new;
        break
    end
    R_expected = R_new;
    Tt = Tr - R_expected/c; % Step 3 repeat
end

end

function [AZ, EL, RANGE] = compute_azelrange(userECEF, satECEF)
% satECEF is ECEF vector of sat
% userECEF is ECEF vector of the user

% Calculate LLA from userECEF
lla = ecef2lla(userECEF,'WGS84');
ref_lat = lla(1);
ref_lon = lla(2);
altitude = lla(3);
% Take difference of ECEF vectors, conver to ENU depending on ref angle
r_ECEF = satECEF-userECEF;

% Calculting range.
RANGE = sqrt(sum(r_ECEF.^2,2));

% Converting to ENU frame
r_ENU = (ECEF2ENU(ref_lat,ref_lon)*r_ECEF')';
x_E = r_ENU(:,1);
x_N = r_ENU(:,2);
x_U = r_ENU(:,3);

% Calclating azimuth and elevation
AZ = atan2d(x_E,x_N);
EL = asind(x_U./sqrt(sum(r_ENU.^2,2)));

end

function [week_number, tow] = utc2gpstime(utc_datetime)
% Converts utc format to gps accounting for leapseconds as well

    gps_epoch = datetime(1980,1,6,0,0,0,'TimeZone','UTC');
    gps_datetime = datetime(utc_datetime,'TimeZone','UTC');

    seconds_since_gps_epoch = seconds(gps_datetime - gps_epoch);

    week_number = floor(seconds_since_gps_epoch/604800);
    tow = seconds_since_gps_epoch - week_number*604800;
end
